# time

把你输入的事务排成一天的行程。

## 三种用法

**说人话**（网页）

> 明天上午把周报写完，大概一小时，很急

AI 把它翻译成结构化任务，**你确认后**才会存进去。

**网页手动添加**

```bash
.venv/Scripts/python.exe app.py
```

然后浏览器打开 <http://127.0.0.1:8000>

**手机也能用**

```bash
.venv/Scripts/python.exe app.py --lan
```

然后手机连**同一个 WiFi**，打开 `http://<这台电脑的局域网地址>:8000`。
会弹一个口令框，**用户名随便填**，密码是 `.env` 里的 `APP_PASSWORD`。
输一次浏览器就记住了。

> **`--lan` 之前必须在 `.env` 里设好 `APP_PASSWORD`，否则服务拒绝启动。**
> 这是故意的——宁可不让启动，也不让一个没口令的服务裸奔在局域网上。

**命令行**

```bash
py plan.py add "写周报" 60 高           # 事务名 持续分钟 优先级
py plan.py add "开会" 30 高 14:00       # 开始时间可省；省了自动找空档
py plan.py add "评审" 90 中 --date 2026-11-03   # 加到别的日子
py plan.py                              # 看今天的行程
py plan.py plan 2026-11-03              # 看指定那天的行程
py plan.py list                         # 全部事务（按日期排）
py plan.py done 1

py test_plan.py && py test_ai.py                  # 跑测试（用 py）
.venv/Scripts/python.exe test_app.py              # 这个必须用 venv 的 Python
```

> 用 `py` 不用 `python`——这台机器上 `python` 是微软商店的占位垫片，
> 会静默失败（不报错、不输出、退出码 0）。

## 首次安装

```bash
py -m venv .venv
.venv/Scripts/python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
cp .env.example .env      # 然后编辑 .env，填入 AI_API_KEY 和 APP_PASSWORD
```

直连 PyPI 在这台机器上基本不可用，**必须挂清华源**。

**不配 `.env` 也能用**——只是「说人话」那个框会提示你去配，
命令行和手动添加照常。

## 现在能做什么（v0.6）

- 三个入口共用同一套核心逻辑和校验规则
- 说人话 → AI 翻译成任务草稿 → 你逐条确认/删掉 → 才入库
- 手动添加四件套：**事件、开始时间、持续时间、优先级**
- 开始时间**可以留空**——程序自己找空档塞进去
- **每条事务属于某一天**，界面用 `‹ 今天 ›` 前后翻，能翻到未来几天
- **说"明天""下周三"AI 也听得懂**，草稿上会写明是哪天，你确认了才入库
- 定死时间的事务会**冲突仲裁**：优先级高的赢，同级先建的赢，
  输的进**待办栏**并写明原因（"和「写周报」冲突" / "没有 90 分钟的空档"）
- 界面用 ● 标出"你自己定的时间"，一眼分清哪些是程序排的
- **手机能看能用**（`--lan` + 口令），窄屏下行程自动改成两行排布
- 标记完成

**冲突只在同一天之内发生。** 今天的会和明天的会各排各的，
都从 09:00 开始，谁也不挤谁。

**"没写日期"就是"今天"，而且加进去的那一刻就定死了。**
你今天加的「写周报」不会明天自动跑到明天去——日期是这条事务的属性，
不是每次打开现算的。

**AI 报的是"距今几天"，不是日期。** 它说"明天"，程序自己加一天算出
2026-11-02。这样它**根本没有机会写出一个错的日期**——最多写错一个
小整数，而那个数在草稿上看得见、能改。

## 冲突仲裁怎么算的

两个事务的时段重叠时，按这个顺序决定谁留下：

1. **优先级**：高 > 中 > 低
2. **先入原则**：优先级相同时，**先建的那条**留下，后来的进待办栏
3. 输的那条**不占时间**，所以它不会连锁把后面的也挤掉

"首尾相接不算冲突"：10:00 结束和 10:00 开始可以共存，
否则每件事之间都得强行留一分钟空隙。

`09:00–18:00` 这个窗口**只是自动找空档的范围**，不是硬限制。
你写 20:00 的会议就排 20:00。

## 关于口令（`--lan` 时）

用 HTTP Basic：浏览器自己弹框，输一次记住。**我们刻意不写登录页、
不写会话管理**——那两样是 web 里最容易写出漏洞的地方，交给浏览器做更靠谱。

两道保险：

1. **要开放，就必须先有口令。** 没设 `APP_PASSWORD` 时 `--lan` 直接拒绝启动。
2. **`--lan` 时自动关掉调试台。** Werkzeug 的调试台是个能在服务器上跑
   任意代码的 Python 交互环境，本机用没问题，开放出去就是给人递刀。

**它挡得住什么、挡不住什么**，说清楚：

| | |
|---|---|
| ✅ 挡得住 | 同一网络里的人扫到 8000 端口、打开你的页面、翻你的数据、**用你的密钥调 AI 烧你的钱** |
| ❌ 挡不住 | 同一网段上有人在抓包。HTTP 上的 Basic 认证，口令在网线上等于明文（base64 只是编码不是加密） |

真要挡后者只能上 HTTPS，那要域名或自签证书，是另一个话题。
**结论：`--lan` 只在可信网络下用**（自己家的 WiFi、手机热点），
别在学校/公司/咖啡馆的网络上开。

## 还不能做什么

- 只有一天一天翻，没有周视图 / 月视图 / 日历
- 事务**加进去就改不了**，也不能删（只能标记完成）
- AI 只说得出**相对**日期（"明天""下周三"）。说"11 月 20 日"这类
  绝对日期它也能换算成天数差，但差太远（一年以外）会被拒掉
- "下周三"到底是哪天，中文本身有歧义（周日起算还是周一起算）。
  程序按周一起算；**草稿上会写明是哪天，看一眼不对就别确认**
- 时间窗写死在 `plan.py` 顶部，改要动代码
- 没有历史记录和统计
- AI 不能追问、不能多轮对话

## 为什么是现在这个样子

技术栈是长出来的，不是一次选定的：

| 版本 | 加什么 | 栈 |
|---|---|---|
| v0.1 | 命令行排程 | Python + JSON |
| v0.2 | 网页界面 | + Flask + HTML |
| v0.3 | AI 翻译人话 | + requests + 外部 API |
| v0.4 | 固定开始时间 + 冲突仲裁 + 待办栏 | 没加依赖，纯逻辑 |
| v0.5 | 手机端适配 + 口令门 | + hmac（标准库），仍无新依赖 |
| **v0.6** | **日期：能翻到未来几天** | **+ datetime（标准库），仍无新依赖** |
| v1.0 | 日历、提醒 | 才需要真正的架构 |

每加一层，就多一处 AI 可能写错、而我还没能力验证的地方。
所以一次只加一层。

## 架构一句话

```
浏览器 ──HTTP/JSON──> app.py ──┬──> plan.py     （排程 + 校验，纯函数）
（界面）              （路由）   └──> ai.py ──> 外部 AI
                                       （只翻译，不排程）
```

**AI 只负责把话翻译成数据，排时间永远由 `plan.py` 做。**
排时间是确定性问题（有唯一正确答案），AI 不可复现、算术不可靠；
翻译是语义问题（没有唯一答案），才是 AI 该干的。

`validate_task` 是全项目唯一的校验入口——命令行、网页、AI 三条路都走它。

**AI 抽开始时间时只认具体钟点。** 用户说"三点开会"，AI 填 `15:00`；
只说"下午要开会"，AI 填 `null` 交给程序找空档。
猜错一个钟点比留空更糟——留空至少是自洽的。

**日期这条规矩执行得更彻底：AI 连日期都不许说，只许说"距今几天"。**
"明天"→1，"下周三"→算出差几天。加日期那一步由 `shift_day()` 做。
理由同上，而且更强：**猜错一个日期比猜错一个钟点更难发现**——
钟点错了当天就看得见，日期错了要等到那天才知道。
把它压成一个小整数，就变成一眼能验的东西了。

## 数据

事务存在 `tasks.json`，**不进 git**。换机器时手动拷一份。
密钥存在 `.env`，**也不进 git**。

一条事务长这样。`start` 是"从零点起的分钟数"，**没有这个键 = 没定时间**；
`date` 是 `'YYYY-MM-DD'`：

```json
{"id": 1, "name": "写周报", "minutes": 60, "priority": "高", "done": false, "start": 570, "date": "2026-11-01"}
```

`date` 是 v0.6 才加的，**老数据里没有这个键**。读的时候把"没有日期"
当成"今天"——那时候所有事务本来就只存在于"今天"，行为跟以前一模一样。
