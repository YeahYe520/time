# time

把你输入的事务排成一天的行程。

## 跑起来

```bash
py plan.py add "写周报" 60 高      # 添加事务：名称 分钟 优先级
py plan.py                         # 看今天的行程
py plan.py list                    # 列出全部事务
py plan.py done 1                  # 标记 #1 已完成
py test_plan.py                    # 跑测试
```

> 用 `py` 不用 `python`——这台机器上 `python` 是微软商店的占位垫片，
> 会静默失败（不报错、不输出、退出码 0）。

## v0.1 能做什么

- 添加事务：名称、预计分钟数、优先级（高/中/低）
- 排进 09:00–18:00 的时间窗
- 排序规则：优先级高的在前；同优先级下短任务在前（能塞进更多事）
- 排不下的单独列出来，不占时间
- 标记完成，完成的不再参与排程

## v0.1 还不能做什么

- 时间窗写死在 `plan.py` 顶部，改要动代码
- 没有历史记录和统计
- 没有界面
- 不考虑"必须几点开始"的固定事务（比如"3点开会"）
- 不跨天规划

## 为什么是现在这个样子

第一个版本刻意做成**一层技术栈**（Python + JSON 文件），
为的是先跑通「输入 → 排程 → 看到结果」这条回路。

技术栈是长出来的，不是一次选定的：

| 版本 | 加什么 | 栈变成 |
|---|---|---|
| v0.1 | 命令行排程 | Python + JSON |
| v0.2 | 存历史、查统计 | + SQLite |
| v0.3 | 网页界面 | + HTML |
| v1.0 | 日历集成、提醒 | 才需要真正的架构 |

每加一层，就多一处 AI 可能写错、而我还没能力验证的地方。
所以一次只加一层。

## 数据

事务存在 `tasks.json`，**不进 git**（内容天天变，进仓库只会让 `git status` 变脏）。
换机器时手动拷一份。
